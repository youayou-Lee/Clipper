# Clipper 攻击链防守者映射

> Phase 2(方法论见 Issue #23):针对 `attack-chain.md` 构建的完整攻击链,逐环节做
> **检测点 → 对策 → 可落地性** 映射。原则:对策从链路推导;防守方天然无解的环节
> 诚实标注,不硬凑。
> 信号可见位置缩写:【端】端点文件/注册表/进程、【网】网络流量、【行】行为遥测(EDR/ETW)、
> 【链】链上数据、【人】仅人类直觉/教育可及。

## 总览:防守方在各环节的胜负手

| 环节 | 防守难度 | 一句话结论 |
|---|---|---|
| §1 分发 | ★★★☆☆ | 平台侧治理为主,端点侧无力——理论上应评更高难度,但用户教育(警惕绕过保护的安装)是成本低、杠杆高的对策,且平台治理在收紧,故给三星 |
| §2 免杀 | ★★★★☆ | 沙箱被环境密钥化系统性失效;可靠信号只剩行为遥测与"哑弹"异常 |
| §3 加载/持久化 | ★★☆☆☆ | 检测点最密集、信号最强——脚本进程链与持久化键是高价值告警 |
| §4 劫持/变现 | ★★☆☆☆ | **剪贴板行为本身是强信号**;链上地址池聚类可事后溯源 |
| 变现追回 | ★★★★★ | 链上不可逆,基本无解,只能前置拦截 |

| 检测点 | 可见位置 | 对策 | 可落地性 |
|---|---|---|---|

## 5. 攻防不对称(诚实记录)

1. **分发端无解**:平台治理与用户教育是唯一对策,端点产品天然缺席;攻击者买广告位的预算,防守方没有对等的"反广告"手段。
2. **沙箱时代红利属于攻击者**:环境密钥化 + TDS 过滤让"先在沙箱里跑一遍"的范式系统性失效,安全产业的主要动态检测手段对这类样本近视。
3. **信誉基础设施可被污染**:VT 投票、下载量、star 数——防守方依赖的每个输入都在被攻击者经营;需要多源交叉,单源信誉不可用。
4. **资金不可逆**:变现端零拦截可能,一切防御必须前置到"粘贴之前"——这正是本项目存在的理由。
5. **防守方优势**:clipper 的"被动等待+常驻"本性,使其必须留下持久化与进程行为的长期痕迹——它不像 ransomware 一样一击即走,**时间站在检测这一边**;且剪贴板替换需要攻击者地址上链,链上可溯源性是长期复仇的种子。
